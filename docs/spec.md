# Nextomic Builder: Product Spec

Nextomic is a self-hosted visual builder for reactive, responsive, dynamic, complex websites and web apps. Output targets: Next.js and Astro. It combines the best of Bricks Builder (classes, IDs, design system, themes, dynamic data), FlutterFlow (queries, app state, action flows, authentication, integrations), and Instatic (self-hosted, own database, media manager).

Design sources are in `blueprint/` (see `ui-reference.md` for the index, coverage, and the rules for following them).

## Principles

1. Everything is JSON. Pages, templates, themes, classes, variables, actions, and queries are data; the renderer and exporter produce code.
2. Platform and built apps are separate. The platform runs on its own Postgres + Better Auth. Supabase/REST are integrations for built apps. Builder auth and built-app auth are different systems.
3. Output has no builder lock-in. Exported projects run anywhere with no Nextomic server, and still contain `nextomic/project.json` so the builder can re-import and edit them.
4. One source of truth per concern: schema in `packages/schema`, builder UI tokens in `blueprint/tokens.json`, built-site design in project data (variables, classes, themes).
5. Never mix builder UI styling with built-site styling. The builder UI uses HeroUI + Tailwind. Built sites use the generated Nextomic CSS framework and the project's themes (see `design-system.md`).
6. Dynamic data works everywhere (see `elements.md`).
7. Runtime: Bun primary, Node (latest LTS) supported. CI runs tests on both.
8. Follow the designs. Ask when something is not designed.

The saved-accounts screen built earlier the same day was removed (migration `0007_env_smtp.sql` drops `smtp_accounts` and `email_templates`). Platform email goes through the queue in `server/mail/*`. Email verification is enforced only when `SMTP_HOST` is set at start.
- Auth origin (2026-11-08): Better Auth gets `baseURL` and `trustedOrigins` explicitly from `BETTER_AUTH_URL` (normalized to its origin) plus optional `BETTER_AUTH_TRUSTED_ORIGINS`, so behind Traefik links and the origin check use the public address.
- Supabase page fixes and app auth settings (2026-11-08, owner request): Number is replaced by Int and Float (old Number reads as Float, Integer as Int); lists display as `Type[]`. Supabase favorites stars were dropped: `*` marks required columns. Postgres enums can be saved into app enums. App Settings gets a Home page select and an Authentication group (`appAuth`). Dynamic data: User = built-app user; Nextomic User = builder account. JWT tags were NOT added: `app-auth.md` section 2 forbids raw tokens in dynamic data.
- Query loops (2026-11-08, owner decisions, Phase 4e): only Container and Section have query loops, in an Element tab group "Query Loop" (Enable Query Loop, Loop name, Query Type Supabase or REST, then the source's settings; full list in `dynamic-data-and-actions.md` section 3). Query values reach only the element's descendants; the query is named "<element name> (<query type>)". Elements with a query show an orange database icon in the Navigator. Live sites render queries on the server first, then the client runtime takes over (refetch, infinite scroll, realtime). The canvas fetches live (memory only). The dynamic data bolt is yellow everywhere and the CSS variable picker icon sky blue.
- Query loop runtime (2026-11-08, owner decision, Phase 4e step 5): realtime loops subscribe from the visitor's browser with the project's Supabase URL and anon key. The anon key is public by Supabase's design (RLS and the Realtime publication decide what streams), so pages with a realtime loop receive it; no other page, export or builder screen does, and the service role key is never used. The browser client is `@supabase/realtime-js` 2.118.0 behind `@nextomic/integrations/realtime` (the platform still never imports `@supabase/*` directly). Infinite scroll and realtime reloads go through the public site endpoint `POST /api/site/<projectId>/loop`, which takes only the page route, query string, loop key and offset and fills every template on the server. It is a Pages Router API route because App Router routes cannot render React to a string; with a `pages` directory present Next types `useSearchParams`/`usePathname` as nullable.
- API Data / REST (2026-11-08, owner decisions, Phase 4c): one REST connector per project holds all groups and calls. Groups have name, base URL, shared headers, shared authentication (None, Bearer, Basic, API key) and Include credentials. Ungrouped calls have every setting themselves. Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS, QUERY. The circle on header lines is a clear (X) button. The Test API tab follows FlutterFlow's layout (Preview and Test, Response Type with JSON Paths and Recommended) with a JS JSON-path reader (`$`, `.name`, `[n]`, `[:]`). The JSON body editor formats and reports errors. Revised the same day: API inputs take only `[variables]` (no dynamic data; typing `[` opens a variable list), groups have shared variables, calls have a Query tab, and the eye picks JSON paths for the response viewer. Variable types use the app's type list (Int and Float, not Integer and DateTime). Builder tests accept sample `jwt`/`user_ip`; built apps resolve them on the server only.
- Token tags (2026-11-08, owner decision, replaces "JWT tags were NOT added" above): with app authentication on, App Settings > Authentication offers two switches, both off by default. "Keep token data as dynamic data" adds ONE JSON tag, `{{user.jwt}}`: the access token's claims, decoded on the server from the session cookie and refreshed with the session. Any claim is read with dot notation (`{{user.jwt.app_metadata.role}}`). This keeps the User group from filling up with one tag per claim. "Expose the raw access token" is an opt-in that adds `{{user.accessToken}}` with a warning; it is never given to custom code elements. API calls should still use the server-filled `[jwt]` variable.
- Supabase connector (2026-11-08, owner decision): only the anon key, in the builder and in built apps; no Supabase in Docker. The schema comes from PostgREST's OpenAPI document at `/rest/v1/`, buckets from `/storage/v1/bucket` (RLS decides what the anon key sees). One Supabase connection per project, named "Supabase". Tests use the owner's instance through `E2E_SUPABASE_*` variables in the root `.env`.

Email change is our own flow (`server/account.ts`): hashed 6-digit code in the `verification` table, sent to the new address. Password change uses the `emailOTP` reset. Password rules come from `AUTH_PASSWORD_POLICY` (`basic`, `medium` default, `strong`, `very-strong`; `lib/password-policy.ts`), checked in a `hooks.before` handler. Migration `0008_auth_security.sql` adds `two_factor`, `passkey` and `user.two_factor_enabled`. QR codes use `uqr` (rendered in the browser as an SVG data URL).
- Profile images (2026-11-08): stored through the storage adapter at `avatars/<userId>/<random>.<ext>`, served by `/avatars/<userId>/<file>`, link saved in `user.image`. Avatars without an image show the first letter of the name.

## Glossary

Project, Page, Template, Theme, Color mode, Element (node), Class, Variable, Query, Loop, Binding, Condition, Action flow, Connector, Auth provider, Dynamic data, Scope.

- Canvas view: plain mouse wheel zooms around the cursor (0.1x to 4x), Shift+wheel pans, holding the middle button drags. The iframe forwards wheel and middle-button events to the editor through validated postMessage. The frame grows to the page height, so the canvas pans instead of scrolling inside the iframe. Rotate swaps a non-base breakpoint to landscape width (preview only).
- Dragging onto the canvas: while a drag is active a shield covers the iframe; the editor sends pointer coordinates, the canvas hit-tests with elementFromPoint and draws the drop marker, then the drop uses the last reported target. Nothing from the iframe can read the builder.
- Exactly one home page per project: saving a page with isHome set clears the flag on all others in the same transaction.
- Publish is a joined split control. Publish puts every page with includeInPublish live as a snapshot (pages.published_snapshot, projects.published_at/published_settings); the arrow holds Save, Preview draft, Version history and Unpublish. Public URL: /site/<projectId>/<route> reads ONLY snapshots with no session. Drafts are only served by /preview/<projectId> to signed-in project members. Pages with requiresAuth are not served publicly until end-user auth exists.
- Breakpoint order is derived from width, never set by hand: larger-than-base ("up") widest first, then the base, then "down" widest first (sortBreakpoints in packages/schema). The manager has no reorder buttons and re-sorts when a width or kind is settled.
- "Generate element ID automatically" is an App Settings option (project-wide), not a per-element switch.
- Element identity input: one field for classes and the ID. Plain text is a class, #text is the ID. Classes are stored by name in classIds until the class manager (Phase 2) and render as the class attribute.
- Fields get a bolt: Element-tab fields insert {{param.x}} / {{state.x}} tokens (MixedText); design-value bolts are shown disabled until the dynamic data phase.
- Dropdowns are HeroUI Select via SelectField. Inside a scrolling modal React Aria closes the list on the stray scroll that opening causes, so SelectField ignores scroll for 400 ms after opening.
- Saving is explicit (Save, Ctrl+S, Publish); there is no autosave. Unsaved edits are lost on refresh, switching pages warns, and preview and the public site show only saved or published content. The Publish control shows a status dot: red unsaved, orange saved draft, green published; Publish becomes a disabled "Published" when the saved draft equals what is live (server-side comparison).
- Canvas, preview and published pages share one base stylesheet (`BASE_CSS` in `packages/renderer`), so the three look the same. The element menu (right-click) adds a `hidden` flag on element nodes (hidden in editor and output).
- CSS text editing uses PostCSS (`packages/schema/src/css-text.ts`); a rule maps to the StyleMap only when its selector is exactly the target plus an optional pseudo state, everything else is kept in `raw` and output verbatim. Code fields use syntax colors (own tokenizer, no dependency).
- Class and variable renames/deletes also rewrite the other saved pages on the server (version bump), then the open page is saved in the same step. Classes are still stored by name. Variables live in `ProjectSettings.variables` and are output as `:root{--nxt-*}`.
- Pseudo states are chips beside the class chips (single click). An element ID cannot be removed while "Generate element ID automatically" is on, and it is active whenever no class is selected.
- Element panel (Phase 2): the ID field is read-only until the pencil is pressed; class chips activate on double click only and everything not active is faded; pseudo state chips are violet/pink. Design values get a unit button (length properties) and a color palette button (color properties) in place of a variable button on every field. Design-value bolts stay disabled because style values are not resolved at render time until the dynamic data phase. Palette names are the variable `group`; applying a palette in Design System > Colors saves immediately. Themes have `allowModeSwitch` (default on).
- Container elements default to a flex column (`BASE_CSS`, `:where(...)` so it never outranks user styles). Picker hover previews live in the editor store (`stylePreview`) and are drawn on a copy of the tree sent to the canvas.
- Fonts (Phase 2): metadata in `ProjectSettings.fonts`, files in storage under `fonts/<projectId>/<fontId>/`, served by the app at `/fonts/...`; no `project_fonts` table (settings JSON versions and publishes with the project). Google Fonts come through the Fontsource API and jsDelivr behind a host allowlist, so no request goes to Google at build or run time. Uploads need the rights checkbox and are validated by magic bytes. Only `active` fonts produce `@font-face`. Open items are listed under Phase 2 in `phases.md`. - Themes (Phase 2): `ProjectSettings.themes` (`packages/schema/src/theme.ts`). - 2026-11-20 Builder storage on Supabase Storage (owner decision): three private buckets, served only through builder routes (SVG sanitizing, content types and nosniff stay). `nextomic-builder-assets` (builder's own files, reserved), `customer-data/<user-uid>/user-image/<file>`, `app-uploads/<workspace-uuid>/<project-uuid>/{media-assets/<type>/<file> (type = the mime top level: image, video, audio, application...), media-variants/<asset-uuid>/<etag>-<width>.webp, fonts/<font-id>/<file>, icon-libraries/<file>, screenshots/<kind>/<id>.webp}`. The adapter uses the Storage REST API with the secret key (the S3 endpoint failed signature checks from the container, so the S3 adapter was removed). Cleanup: triggers on `public.users`, `nextomic_builder.workspaces` and `nextomic_builder.projects` queue the folder in `nextomic_builder.storage_deletions`; the builder empties queued folders through the Storage API (on start, every 20 seconds, and right after in-app deletes). Objects are never deleted with SQL: Storage refuses it and it would leave files behind. Media purges queue the asset folder. Old local files are not copied (fresh start). The Storage service's `FILE_SIZE_LIMIT` must be at least 200 MB (largest video).

- 2026-11-20 Image compression on upload (owner decision): App Settings > Media has "Compress uploaded images" (default on) and a five-step quality picker (40, 50, 60, 70, 80 percent; default 60), saved in `ProjectSettings.imageCompression`. The browser converts the image to WebP before upload (`lib/image-compress.ts`, canvas), so the server does no work. PNG, JPG, WebP, AVIF and BMP are converted when the result is smaller; SVG, GIF, video, audio and PDF upload unchanged. HEIC and HEIF are always converted (no browser shows them): Safari decodes them natively, other browsers through the `heic-to` WebAssembly decoder (1.6.7, loaded only when a HEIC file is chosen; LGPL-3.0, from libheif). A HEIC file that cannot be converted is refused with a message. Size limit (longer side, proportions kept, never enlarged): 1500 px for project uploads when compression is on (1536 x 2048 becomes 1125 x 1500), 600 px for builder-level images (becomes 450 x 600). With compression off the file uploads raw, within the bucket limit; only HEIC is still converted, at full size, because the server cannot store it. Builder-level images (profile image) always convert to WebP at 60 percent, no setting. App Settings is now grouped (General, Media, Pages, Editor, Authentication) with dividers; help text moved into info tooltips.
- 2026-11-20 Media files keep their own names and the library row stores only what Storage does not know (owner decision). Uploads go to `media-assets/<type>/<file name>`: the uploaded name when it is plain (ASCII letters, digits, space and . _ - ( ), up to 100 characters), otherwise `<asset-uuid>.<ext>`; the extension is the one the bytes prove. A taken name becomes `name-2.ext`, `name-3.ext` (the upload is refused by Storage with no overwrite, so two uploads never share a file). Resized copies moved to `media-variants/<asset-uuid>/<etag>-<width>.webp`. `media_assets` lost `mime`, `size`, `hash`, `file_name`, `original_name` and `kind` and gained `object_id`, a foreign key to `storage.objects(id)` with ON DELETE CASCADE (the object id survives upsert and move; deleting a file in Studio removes its library row). The view `nextomic_builder.media_library` joins the two: file name from the object path, mime and size from `metadata`, ETag from `metadata.eTag`. `width` and `height` stay in the row: Storage does not hold them, and the public route needs them to skip a resize and to answer 304 without reading the file. The library Name starts as the file name without extension, cannot contain dots, and changes only the library name (the stored file keeps its name, so URLs never break). Missing title filter removed (every file has a name). The details panel shows Resolution and no longer shows the path. Migration 0003 removed the media rows that existed before (test data) and queued their folders for deletion. A queued single file is removed by exact path, never by prefix.
